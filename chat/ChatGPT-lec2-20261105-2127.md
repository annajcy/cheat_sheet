# 二、开始学习：模块 1 - 基础概念与 Locality

## 1\. Latency、Throughput、Bandwidth

这是课件 P4-11 的三个基本指标。

| 概念 | 含义 | 关注什么 |
|--------|--------|--------|
| Latency（延迟） | 完成一次操作需要多久 | 时间 |
| Throughput（吞吐量） | 单位时间实际完成多少工作 | 实际速率 |
| Bandwidth（带宽） | 理论最大数据传输速率 | 最大速率 |

例如，假设某个存储系统：

- Bandwidth = 100 GB/s
- Throughput = 80 GB/s
- Latency = 100 ns

说明它理论上每秒最多传输 100 GB，实际上达到 80 GB/s，而一次访问可能需要等待 100 ns。

要记住：

$$
\boxed{\text{Throughput}\leq \text{Bandwidth}}
$$

并且：

$$
\boxed{\text{High Bandwidth}\not\Rightarrow\text{Low Latency}}
$$

也就是带宽很高，不代表单次访问就快。fileciteturn0file0L134-L146

## 2\. Memory Hierarchy（内存层次）

基本规律：

$$
\boxed{\text{Fast Memory} \Rightarrow \text{Small \& Expensive}}
$$

CPU 不希望每次计算都去 DRAM 取数据，而是尽量使用 Registers 和 Cache 中的数据。

所以算法性能不仅取决于计算次数，还取决于数据有没有被放在靠近处理器的位置。

## 3\. Temporal Locality（时间局部性）

**短时间内重复访问同一份数据。**

例如：

```python
for i in range(1000):
    x += 1
```

`x` 被不断重复访问。

如果数据已经在高速存储中，就可以避免再次从慢速内存读取。

关键在于 **soon（很快）**。

课件强调，即便一个元素被访问两次，如果两次之间隔了数百万次其他内存访问，它也可能早已被 Cache 淘汰。

这个间隔可以用 Reuse Distance 来衡量。fileciteturn0file0L265-L278

## 4\. Spatial Locality（空间局部性）

**访问一个地址后，很快访问附近的地址。**

例如：

```python
for i in range(1000):
    sum += A[i]
```

访问顺序：

$$
A[0]\rightarrow A[1]\rightarrow A[2]\rightarrow \cdots
$$

因为内存通常按连续的数据块（Cache Line）读取，所以访问 `A[0]` 时，附近的数据可能已经被一起加载。

这就是 Spatial Locality。

两种局部性的区别，可以简单记成：

$$
\boxed{
\begin{aligned}
\text{Temporal}&:\ \text{Same data, soon}\\
\text{Spatial}&:\ \text{Nearby data, soon}
\end{aligned}
}
$$

# 二、模块 2：Memory Hierarchy

对应 L02.pdf 第 14、24–36 页

这一部分主要讨论 CPU、GPU、FPGA 如何组织存储器。

## 1\. CPU Memory Hierarchy

为什么这么设计？

因为高速内存通常具有两个特点：

- 速度快，但是容量小、成本高。
- 低速内存容量大，但是访问延迟高。

因此，CPU 希望把频繁访问的数据保留在靠近计算核心的高速存储中。

例如，CPU 读取 `A[0]` 时：

1. 先检查 L1 Cache。
2. L1 没有，就查 L2、L3。
3. 如果都没有，再从 DRAM 中读取。

这就涉及两种情况：

$$
\boxed{\begin{aligned}
\text{Cache Hit}&:\ \text{数据已经在 Cache 中}\\
\text{Cache Miss}&:\ \text{需要从更低层读取}
\end{aligned}}
$$

后续模块 5 和 6 会专门分析 Cache Miss。

## 2\. GPU Memory Hierarchy

GPU 和 CPU 的设计理念不同：GPU 需要支持大量线程同时计算。

课件第 28 页的 GPU 结构图，核心可以简化成以下形式。

Streaming Multiprocessor (SM)

**Registers**

每线程私有

**Shared Memory / L1**

片上，靠近 SM

**L2 Cache**

整个 GPU 共享

**Global Memory (GDDR / HBM)**

片外 DRAM，大容量、高访问延迟

### GPU 的主要内存类型

| 类型 | 作用域 | 主要特点 |
|--------|--------|--------|
| Registers | Thread 私有 | 最快，容量有限 |
| Shared Memory | Block 内线程共享 | 片上，可显式管理 |
| L1 Cache | SM 附近 | 硬件管理的缓存 |
| L2 Cache | 整个 GPU 共享 | 缓存 Global Memory 数据 |
| Global Memory | 全局访问 | 容量大，但延迟高 |
| Local Memory | Thread 私有 | 实际通常存放在片外显存中 |

这里特别注意两个容易混淆的概念。

**① Shared Memory 和 L1 Cache 有什么区别？**

两者都位于片上，但管理方式不同：

- L1 Cache：硬件自动决定缓存哪些数据。
- Shared Memory：程序员可以主动把数据加载进去，供同一个 Block 内的线程复用。

例如矩阵乘法中，多个线程会重复使用同一小块矩阵数据。可以先把它加载进 Shared Memory，再反复计算，减少 Global Memory 访问。

**② Local Memory 为什么反而慢？**

这是 CUDA 中容易误解的地方。

Local Memory 的 *Local* 指的是**每个线程私有的地址空间**，而不是物理位置靠近计算核心。

它通常位于设备 DRAM 中，可能用于：

- Register Spilling：寄存器不足时把数据溢出到 Local Memory。
- 存储较大的线程私有数组。

所以：

$$
\boxed{\text{Local Memory}\neq\text{Fast On-Chip Memory}}
$$

课件还介绍了 Constant Memory（适合广播式读取常量）和 Texture Memory（适合具有二维、三维空间局部性的访问）。fileciteturn0file0L403-L525

## 3\. FPGA Memory Hierarchy

FPGA 和 CPU/GPU 的一个重要区别是：**FPGA 设计者能够更直接地决定片上存储器的组织和使用方式。**

课件将 FPGA 内存分为两类：

| 位置 | 类型 | 特点 |
|--------|--------|--------|
| On-Chip | Registers / Flip-Flops | 最快，容量小 |
| On-Chip | LUTRAM | 小规模片上存储 |
| On-Chip | BRAM / URAM | 容量相对更大的片上存储 |
| External | SRAM / DRAM | 外部存储器 |
| External | Flash | 非易失性存储，较慢 |

假设 FPGA 需要处理一批矩阵数据：

- 大矩阵存放在外部 DRAM 中。
- 当前需要计算的一小块矩阵加载到 BRAM。
- 计算过程中的临时数据放在 Registers。

这样可以减少不断访问外部 DRAM 的次数。fileciteturn0file0L334-L383

## 4\. 三个平台的核心区别

|  | CPU | GPU | FPGA |
|--------|--------|--------|--------|
| 主要高速存储 | Registers、Cache | Registers、Shared Memory、Cache | Registers、BRAM、URAM |
| 数据管理 | Cache 主要由硬件管理 | 硬件缓存 + 显式 Shared Memory | 片上存储可由设计者显式组织 |
| 优化重点 | 提高缓存命中率 | 数据复用和线程并行 | 数据流、片上缓冲与带宽 |

这一部分不用背具体有多少 KB/MB，重点是理解：

$$
\boxed{\text{减少慢速内存访问} \Rightarrow \text{提高计算效率}}
$$

# 二、模块 3：Blocking / Tiling

L02.pdf P37-44，结合 P78-80 的 Cache Miss 分析

本节的核心问题：

**同样是 $\Theta(n^3)$ 的矩阵乘法，为什么 Blocking 能显著减少 Cache Miss？**

## 1\. Naïve Matrix Multiplication

对于两个 $n\times n$ 矩阵：

$$
C_{ij}=\sum_{k=0}^{n-1}A_{ik}B_{kj}
$$

课件第 38 页采用的循环顺序是：

```python
for i in range(n):
    for j in range(n):
        for k in range(n):
            C[i][j] += A[i][k] * B[k][j]
```

时间复杂度：

$$
\boxed{W(n)=\Theta(n^3)}
$$

因为有三层循环，每层执行 $n$ 次。

但是三个矩阵的访问模式完全不同。

## 2\. 三个矩阵的访问模式

假设矩阵采用 **Row-major（按行连续存储）**。

固定 i=0、j=1，观察 k 从 0 到 3 的访问

**A$$i$$$$k$$：按行访问**

连续地址，Spatial Locality 好

**B$$k$$$$j$$：按列访问**

跨行跳跃，Spatial Locality 差

橙色和蓝色格子表示一次内层 k 循环访问的元素。

具体而言：

| 矩阵 | 内层循环访问 | Locality |
|--------|--------|--------|
| A | `A[i][0], A[i][1], ...` | Spatial 好 |
| B | `B[0][j], B[1][j], ...` | Spatial 差 |
| C | `C[i][j]` 反复更新 | Temporal 好 |

这也是课件第 39-40 页的结论：C 的时间局部性最强，B 的空间局部性最差。fileciteturn0file0L560-L581

## 3\. 为什么 B 容易产生大量 Cache Miss？

首先定义：

- $M$：Cache 可以存储的元素数量。
- $b$：每条 Cache Line 可以存储的元素数量。
- $Q(n)$：整个算法产生的 Cache Miss 次数。

假设一条 Cache Line 能存 4 个元素。

对于一行 4 个元素：

$$
B[0][0],B[0][1],B[0][2],B[0][3]
$$

顺序读取这 4 个元素，在冷缓存情况下通常只需要 **1 次 Cache Miss**，因为第一次读取就将整条 Cache Line 加载进来了。

但是如果按列读取：

$$
B[0][0]\rightarrow B[1][0]\rightarrow B[2][0]\rightarrow B[3][0]
$$

它们位于不同 Cache Line，冷缓存下可能产生 **4 次 Cache Miss**。

当矩阵非常大，且这些 Cache Line 在下一次复用前就已经被淘汰时，问题会更加严重。

对于 Naïve 乘法：

$$
\underbrace{n^2}_{(i,j)}
\times
\underbrace{n}_{k}
=n^3
$$

也就是 B 总共被访问 $n^3$ 次。

在课件第 78 页所讨论的、B 的列访问无法有效保留在 Cache 中的大矩阵情形下：

$$
\boxed{Q_{\mathrm{naive}}(n)=\Theta(n^3)}
$$

注意：这不是所有矩阵大小下都成立。如果缓存能够保留 B 各行对应的 Cache Line，或者整个矩阵能放入 Cache，Miss 次数就会明显减少。课件最后也专门区分了这些情况。fileciteturn0file0L1256-L1320

---

## 4\. Blocking / Tiling 是什么？

核心思想：

**不要每次都扫描整个大矩阵，而是把矩阵拆成小块，在 Cache 中尽量完成计算。**

一个 4×4 矩阵按 2×2 分块

每个小块可以单独加载到 Cache，反复使用后再处理下一块。

举个例子：

$$
C_{11}=A_{11}B_{11}+A_{12}B_{21}
$$

这里的 $A_{11},B_{11},C_{11}$ 都是小矩阵，而不是单个元素。

只要三个小块能同时放进 Cache，就能在其中完成大量乘加运算。

## 5\. Blocking 如何降低 Cache Miss？

设每个 Tile 的尺寸是 $S\times S$。

要同时保存 A、B、C 三个 Tile，理想化容量条件是：

$$
\boxed{3S^2\le M}
$$

这里 $M$ 以元素数量计，暂时忽略其他缓存开销。

一次 Tile 乘法：

$$
C_{\mathrm{tile}} \mathrel{+}=
A_{\mathrm{tile}}B_{\mathrm{tile}}
$$

需要：

$$
\text{Computation}=\Theta(S^3)
$$

但所涉及的数据只有：

$$
\text{Data}=\Theta(S^2)
$$

因此：

$$
\boxed{\frac{\text{Computation}}{\text{Data}}=\Theta(S)}
$$

也就是说，**Tile 越大，加载进 Cache 的数据被重复利用的次数通常越多**，前提是它仍能放进 Cache。

进一步，在 Tile 尺寸足够大、每条 Cache Line 得到充分利用且缓存能容纳工作集等常见假设下，可以得到典型分块矩阵乘法的 Cache Miss 上界：

$$
\boxed{
Q_{\mathrm{blocked}}(n)
=
O\left(\frac{n^3}{bS}+\frac{n^2}{b}\right)
}
$$

这个公式是基于课件 Blocking 思路的进一步推导，课件第 37-44 页主要展示了分块方法，没有直接给出这个上界。

其核心推导是：

$$
\begin{aligned}
\text{Tile 乘法次数}&=\left(\frac nS\right)^3\\
\text{每次 Tile 数据传输}&=O\left(\frac{S^2}{b}\right)\\
\text{总 Cache Miss}&=O\left(\frac{n^3}{bS}\right)
\end{aligned}
$$

另计矩阵初始化、结果写回等 $O(n^2/b)$ 项。这里需要 $S\gtrsim b$ 且缓存布局和替换行为足够理想。

对比来看：

| 算法 | 计算复杂度 | Cache Miss（特定假设下） |
|--------|--------|--------|
| Naïve | $\Theta(n^3)$ | $\Theta(n^3)$ |
| Blocked | $\Theta(n^3)$ | $O(n^3/(bS)+n^2/b)$ |

最重要的结论是：

$$
\boxed{\text{运算量不变，但数据搬运显著减少}}
$$

\boxed{Q_{A+B}=O\left(\frac{n^3}{bS}\right)}

因为 C 有额外的数据复用机会。

固定 $I,J$ 两个 Tile 坐标：

$$

对于同一个 $C_{IJ}$，我们会遍历所有 K。

也就是说，同一个输出 Tile 会参与 $n/S$ 次 Tile 乘法。

一共有：

$$
\left(\frac nS\right)^2

个不同的 C Tile。

每个需要 $S^2/b$ 条 Cache Line：

$$
\begin{aligned}
Q_C
&=O\left(\left(\frac nS\right)^2\frac{S^2}{b}\right)\\[4pt]
&=O\left(\frac{n^2}{b}\right)
\end{aligned}
$$

因此：

$$
\boxed{Q_C=O\left(\frac{n^2}{b}\right)}
$$

这一步需要 C Tile 能够在 K 循环期间留在高速存储中。若没有这种保证，仍可使用上一节对每次 Tile 乘法的 $O(S^2/b)$ 上界。

# 八、Tile 大小 $S$ 应该怎么选？

既然：

$$
Q_{\text{blocked}}(n)

个元素，所以基本容量条件为：

$$

得到：

$$
\boxed{S\le\sqrt{\frac M3}}
$$

## 1\. Cache 不是一次只读取一个元素

假设内存中有一个数组：

$$

$$

那么内存会按下面的方式分组：

现在 CPU 依次访问数组：

| 操作 | Cache 状态 | 原因 |
|--------|--------|--------|
| 读取 A$$0$$ | Miss | 将 A$$0$$～A$$3$$ 一起加载 |
| 读取 A$$1$$ | Hit | 已经在 Cache 中 |
| 读取 A$$2$$ | Hit | 已经在 Cache 中 |

| 读取 A$$4$$ | Miss | 加载第二条 Cache Line |
| 读取 A$$5$$～A$$7$$ | Hit | 已经加载 |

最终：

- 访问数组元素：8 次
- Cache Miss：2 次

所以：

$$

这是连续读取、缓存初始为空、地址对齐且没有提前淘汰等条件下的结果。

- 访问 $a_{01}$：Hit。
- 访问 $a_{02}$：Miss，一起加载 $a_{02},a_{03}$。
- 访问 $a_{03}$：Hit。

所以第一行只有 **2 次 Cache Miss**。

整个矩阵有 4 行：

$$
Q_A=\underbrace{4}_{\text{行数}}\times\underbrace{\frac42}_{\text{每行 Cache Line 数}}
=8
$$

推广到 $S\times S$：

$$
\boxed{Q_A=S\times\frac Sb=\frac{S^2}{b}}
$$

到这里，我们只是计算了**把一个 Tile 的所有元素加载进 Cache，需要多少次 Cache Miss**。

## 3\. 为什么三个 Tile 只需要 $3S^2/b$？

因为矩阵乘法：

$$
C_{\text{tile}}\mathrel{+}=A_{\text{tile}}B_{\text{tile}}
$$

涉及三个 Tile。

假设 Cache 足够大，可以同时存下 A、B、C：

$$
3S^2\le M
$$

那么在理想情况下：

$$
\begin{aligned}
Q_A&=\frac{S^2}{b}\\
Q_B&=\frac{S^2}{b}\\
Q_C&=\frac{S^2}{b}
\end{aligned}
$$

因此：

$$
\boxed{Q_{\text{total}}\le\frac{3S^2}{b}}
$$

这里忽略写回流量，假设冷缓存、对齐，并且每个 Tile 的数据加载后不会在使用期间被淘汰。

**关键就在这里：即使矩阵乘法要执行 $S^3$ 次乘加，也不代表需要发生 $S^3$ 次 Cache Miss。**

因为已经加载到 Cache 的数据可以反复使用。

例如 $S=8,b=4$：

$$
\begin{aligned}
\text{乘加次数}&=8^3=512\\
\text{三块数据的 Cache Line 数}&=3\times\frac{8^2}{4}=48
\end{aligned}
$$

也就是说，可以利用大约 48 条 Cache Line 中的数据，完成 512 次乘加，而不是每次乘加都去 DRAM 重新取数据。

这就是 **Blocking 的核心：把数据搬进 Cache 后尽量反复使用。**

## 第一步：Single Buffer 与 Double Buffer

### 1\. Single Buffer

假设处理器要处理两批数据 A 和 B。

每批数据都要经过两步：

1. Load：从慢速内存加载到 Buffer。
2. Compute：使用 Buffer 中的数据进行计算。

只有一个 Buffer 时：

Single Buffer：顺序执行

先加载，再计算；计算完成后才能复用同一个 Buffer。

为什么不能同时 Load B？

因为 Buffer 正在保存 A，计算还需要使用 A。

如果此时直接把 B 写进去，就可能覆盖尚未使用完的 A。

因此，加载和计算只能交替进行。

### 2\. Double Buffer

现在准备两个 Buffer：

- Buffer 1：存放 A，供处理器计算。
- Buffer 2：同时加载下一批数据 B。

Double Buffer：加载与计算重叠

## 第七步：推导 N 批数据的总时间公式

我们已经知道 Double Buffering 可以分为三个阶段：

| 阶段 | 操作 | 耗时 |
|--------|--------|--------|
| ① 初始化 | Load 第一批数据 | $T_L$ |
| ② 重叠阶段 | Compute 当前批 + Load 下一批 | $(N-1)\max(T_L,T_C)$ |
| ③ 收尾 | Compute 最后一批 | $T_C$ |

将三个阶段相加：

$$
\boxed{
T_{\text{double}}
=
T_L+(N-1)\max(T_L,T_C)+T_C
}
$$

这就是课件 P62 的 Double Buffering 性能公式。课件使用近似号，因为实际系统还可能存在同步和调度开销。fileciteturn0file0L929-L939

### 为什么中间使用 max，而不是加法？

因为 Load 和 Compute 可以并行。

例如：

$$
T_L=3\text{ ms},\qquad T_C=5\text{ ms}

两个操作同时开始：

- Load 经过 3 ms 完成。
- Compute 经过 5 ms 完成。

必须等两者都完成才能进入下一阶段，因此：

$$
T_{\text{overlap}}=\max(3,5)=5\text{ ms}
$$

而不是 $3+5=8\text{ ms}$。

## 第一步：Fully Associative Cache（全相联缓存）

之前我们知道：

**Cache 能保存很多条 Cache Line。**

但现在有一个新问题：

假设 Cache 能存 8 条 Cache Line，那么从 DRAM 加载的一条数据，究竟应该放到 Cache 的哪个位置？

不同的 Cache Model 就是用不同方式解决这个问题的。

### 1\. Fully Associative 的工作方式

**任意一个 Memory Block 可以放在 Cache 的任意位置。**

例如，课件 P65–66 使用：

$$
M=32\text{ bytes},\qquad \mathcal B=4\text{ bytes}
$$

注意，这里课件使用字节作为单位；之前 Blocking 中我们用元素数量作为单位。

Cache 一共可以放：

$$
\boxed{\frac M{\mathcal B}=\frac{32}{4}=8\text{ 条 Cache Line}}
$$

Fully Associative Cache 示例

Main Memory

Cache (8 Lines)

示意图：0x0000 放在 Slot 3，0x0020 放在 Slot 0。Fully Associative 不限制它们必须使用哪个 Slot。

注意：

Memory Block `0x0000` 可以放到 Slot 0、Slot 1……Slot 7 中的任意一个。

Memory Block `0x0020` 也一样。

这就是 **Fully Associative**。

### 2\. 如果 Cache 满了怎么办？

假设 8 个 Slot 都满了，现在又要加载第 9 个 Memory Block。

那么必须淘汰一条已有的 Cache Line。

这就需要 **Replacement Policy（替换策略）**。

课件介绍了：

$$
\boxed{\text{LRU = Least Recently Used}}
$$

意思是：**优先淘汰最长时间没有被访问过的数据块。**

例如当前 Cache 中有：

$$
[A,B,C,D]
$$

假设 A 是最久没有被访问的块。

此时需要加载 E，Cache 又已经满了，那么 LRU 就会淘汰 A，放入 E。

### 3\. Fully Associative 的优缺点

| 优点 | 缺点 |
|--------|--------|
| Memory Block 可以放在任意位置 | 查找硬件更复杂 |
| 不会因为固定映射位置而产生 Conflict Miss | 通常需要比较多个 Tag |
| 存储位置灵活 | 替换策略也有额外成本 |

下一个 Direct Mapped Cache 就是用更简单的映射方式来降低硬件复杂度，但代价是可能出现 Conflict Miss。

## 第二步：Direct Mapped Cache

### 1\. Direct Mapped 和 Fully Associative 有什么区别？

- **Fully Associative**：Memory Block 可以放在任意 Cache Slot。
- **Direct Mapped**：每个 Memory Block 只能放在一个固定的 Cache Slot。

假设：

$$
M=32\text{ bytes},\qquad \mathcal B=4\text{ bytes}
$$

那么 Cache 有：

$$
\frac M{\mathcal B}=\frac{32}{4}=\boxed{8\text{ 个 Slots}}
$$

问题来了：一个 Memory Block 应该映射到哪个 Slot？

### 2\. 推导地址映射公式

假设 CPU 想访问内存地址 $a$。

**第一步：确定它属于哪个 Memory Block。**

因为每个 Block 包含 $\mathcal B$ 个字节：

$$
\boxed{\text{Block ID}=\left\lfloor\frac a{\mathcal B}\right\rfloor}
$$

**第二步：确定它应该放进哪个 Cache Slot。**

Cache 一共有 $M/\mathcal B$ 个 Slot。

我们使用取余运算：

$$
\boxed{
\text{Slot Index}
=
\text{Block ID}\bmod\frac M{\mathcal B}
}
$$

合并起来：

$$
\boxed{
\text{Slot Index}
=
\left\lfloor\frac a{\mathcal B}\right\rfloor
\bmod\frac M{\mathcal B}
}
$$

这就是 Direct Mapped Cache 的核心映射公式。

**True Sharing**

x

同一个变量

Core 0 写 x  Core 1 读 x

**False Sharing**

**x**

**y**

Core 0 写 x  Core 1 写 y

x、y 属于同一 Cache Line

### 1\. 理想模型有两个关键假设

**① Fully Associative**

任意 Memory Block 可以放在 Cache 中的任意位置。

因此，不用考虑 Set 映射引起的 Conflict Miss。

**② Optimal Replacement（最优替换策略）**

当 Cache 满了，模型会选择对未来访问最有利的 Block 进行淘汰，使 Cache Miss 总次数尽可能小。

它不同于之前的 LRU：

- LRU：根据过去的访问记录，淘汰最久未使用的 Block。
- Optimal：知道未来的访问顺序，可以做出最优替换决策。

这个 Optimal Replacement 是理论假设，并不代表真实 CPU 能预知未来。

## 2\. 两个基本参数

课件定义：

$$
\boxed{
\begin{aligned}
M&=\text{Cache Capacity}\\
\mathcal B&=\text{Cache Block Size}
\end{aligned}}
$$

因此 Cache 能容纳：

$$
\boxed{\frac M{\mathcal B}\text{ 个 Blocks}}
$$

例如：

$$
M=64\text{ Bytes},\qquad\mathcal B=8\text{ Bytes}
$$

则：

$$
\frac{64}{8}=\boxed{8\text{ 个 Blocks}}
$$

注意：在这个模型中，我们不再关注 Tag、Index、Way 等硬件实现细节。

## 3\. 两个性能指标

课件还定义：

$$
\boxed{
\begin{aligned}
W(n)&=\text{Work（计算工作量）}\\
Q(n)&=\text{Cache Misses（缓存缺失次数）}
\end{aligned}}
$$

例如，一个算法：

$$

代表执行 $\Theta(n^3)$ 量级的计算操作。

而：

$$
Q(n)=\Theta(n^2/\mathcal B)
$$

表示发生 $\Theta(n^2/\mathcal B)$ 次 Cache Miss。

## 第二步：LRU Lemma（最近最少使用引理）

L02.pdf 第 72 页，课件页码 73

课件给出的定理是：

$$
\boxed{Q_{\mathrm{LRU}}(2M)\le 2Q_{\mathrm{Ideal}}(M)}
$$

我们先理解这个公式的含义，暂时不证明。

### 1\. 公式两边分别是什么意思？

假设有两个 Cache，执行**完全相同的内存访问序列**。

|  | Ideal Cache | LRU Cache |
|--------|--------|--------|
| 容量 | $M$ | $2M$ |
| 映射方式 | Fully Associative | Fully Associative |
| 替换策略 | Optimal | LRU |
| Cache Miss | $Q$ | 最多 $2Q$ |

也就是说：

**如果一个大小为 $M$ 的理想 Cache 产生 $Q$ 次 Miss，那么大小为 $2M$ 的 LRU Cache 最多产生 $2Q$ 次 Miss。**

这正是课件 LRU Lemma 的陈述。fileciteturn0file0L1146-L1150

### 2\. 举个数字例子

假设：

$$
M=64\text{ KB}
$$

一个 64 KB 的 Ideal Cache 产生：

$$
Q_{\mathrm{Ideal}}(64\text{ KB})=100
$$

那么根据 LRU Lemma：

$$
\boxed{Q_{\mathrm{LRU}}(128\text{ KB})\le200}
$$

注意，这里有两个很重要的地方：

- 不是说 LRU 一定产生 200 次 Miss，而是**最多 200 次**。
- LRU 使用的是 **128 KB**，而 Ideal 使用的是 **64 KB**。

### 3\. 为什么要给 LRU 两倍容量？

因为 Optimal Replacement 知道未来的访问顺序，而 LRU 只知道过去。

LRU 可能错误地淘汰即将再次使用的数据。

但是，如果给 LRU 更多缓存空间，它就能够保留更多历史访问的数据，从而弥补替换策略不够聪明的问题。

LRU Lemma 告诉我们：

$$
\boxed{
\text{2 倍 Cache 容量}
\Longrightarrow
\text{LRU Miss 不超过 Ideal 的 2 倍}
}
$$

**注意：这并不意味着相同容量时 LRU 的 Miss 数一定不超过 Ideal 的两倍。**

这也是这个定理有价值的地方：它为现实可实现的 LRU 策略提供了一个相对于理想模型的性能保证。

### 2\. LRU 什么时候会淘汰 A？

$$
\boxed{
\text{LRU Reaccess Miss}
\Rightarrow
\text{Reuse Distance}\ge 2m

这里 Reuse Distance 指两次访问同一 Block 之间，访问过的不同 Block 数量。

# 下一块：Cache-Miss Lemma

L02.pdf P73–74，课件页码 74–75

这部分比 LRU Lemma 更直接，核心就是计算：**读取若干段连续数据，会产生多少次 Cache Miss？**

## 1\. 首先理解问题

假设程序要读取 $r$ 段数据：

$$
S_1,S_2,\ldots,S_r
$$

其中每段数据都是连续存储的，但不同段之间不一定连续。

定义：

$$
\boxed{N=\sum_{i=1}^{r}S_i}
$$

其中：

- $r$：数据段数量
- $S_i$：第 $i$ 段的大小（Bytes）
- $N$：所有数据段的总大小
- $M$：Cache 容量（Bytes）
- $\mathcal B$：Cache Line 大小（Bytes）

## 2\. Cache-Miss Lemma 结论

课件给出了两个条件：

$$
\boxed{
\begin{aligned}
N&<\frac M3\\
\frac Nr&\ge\mathcal B
\end{aligned}}
$$

满足这两个条件，就有：

$$
\boxed{Q\le\frac{3N}{\mathcal B}}
$$

也就是说，读取这些数据所需的 Cache Miss 次数至多为 $3N/\mathcal B$。fileciteturn0file0L1162-L1177

### 为什么是这个公式？

我们先简单看一下：

一段连续数据大小为 $S_i$，考虑它与 Cache Line 边界可能没有对齐。

最多需要约：

$$
\frac{S_i}{\mathcal B}+2
$$

条 Cache Line。

因此 $r$ 段数据总共：

$$
\begin{aligned}
Q
&\le\sum_{i=1}^{r}\left(\frac{S_i}{\mathcal B}+2\right)\\
&=\frac N{\mathcal B}+2r
\end{aligned}
$$

由条件：

$$
\frac Nr\ge\mathcal B
\quad\Rightarrow\quad
r\le\frac N{\mathcal B}
$$

所以：

$$
Q\le\frac N{\mathcal B}+2\frac N{\mathcal B}
$$

最终：

$$
\boxed{Q\le\frac{3N}{\mathcal B}}
$$

这也是课件 P74 的证明思路。fileciteturn0file0L1180-L1203

# 下一步：Tall-cache Assumption

L02.pdf P75，课件页码 76

我们先理解 Tall-cache Assumption，再进入 Submatrix Caching Lemma。

## 1\. 什么是 Tall-cache Assumption？

课件给出的条件是：

$$
\boxed{\mathcal B^2<cM}
$$

其中：

- $M$：Cache 容量
- $\mathcal B$：Cache Line 大小
- $c$：一个足够小的正常数，$c\le1$

在理论模型中，$M$ 和 $\mathcal B$ 都按统一的数据单位计数。

忽略常数后，可以写成：

$$
\boxed{M=\Omega(\mathcal B^2)}
$$

**意思是：Cache 的容量要相对于 Cache Line 的大小足够大。** fileciteturn0file0L1205-L1223

## 2\. 为什么叫 Tall-cache？

我们知道 Cache 可以容纳：

$$
\frac M{\mathcal B}
$$

条 Cache Line。

现在把 Tall-cache 条件：

$$
\mathcal B^2<cM
$$

两边除以 $\mathcal B$：

$$
\boxed{\mathcal B<c\frac M{\mathcal B}}
$$

也就是说，Cache 能容纳的 Line 数量，相对于单条 Line 的大小，要足够多。

例如：

$$
M=4096,\qquad \mathcal B=16
$$

那么：

$$
\mathcal B^2=256,\qquad M=4096
$$

Cache 可以容纳：

$$
\frac{4096}{16}=256\text{ 条 Cache Line}
$$

这样的容量关系就有利于缓存矩阵中的多个连续数据段。

这里要注意：**Tall-cache 是理论分析中的一个假设，不是说 Cache 在物理形状上很高。**

## 3\. 它与后面的矩阵分析有什么关系？

后面我们会研究一个 $n\times n$ 的 Submatrix。

课件希望证明：

$$

$$

但为了应用刚才学过的 Cache-Miss Lemma，需要保证子矩阵的连续数据段足够长，而且整个子矩阵能够放进 Cache。

Tall-cache Assumption 就是用来帮助满足这些条件的。

具体怎么联系到 $n$，我们下一步再推导。

## 第一步：为什么 B 矩阵几乎每次访问都会 Miss？

回顾 Naïve Matrix Multiplication：

```python
for i in range(n):
    for j in range(n):
        for k in range(n):
            C[i][j] += A[i][k] * B[k][j]
```

假设：

- B 矩阵按 Row-major 存储。
- Cache 容量是 $M$ 个元素。
- 每条 Cache Line 有 $\mathcal B$ 个元素。
- 使用 LRU 替换策略。

那么 Cache 最多存储：

$$
\boxed{\frac M{\mathcal B}\text{ 条 Cache Line}}
$$

### 1\. 观察 B 的访问

固定 $i,j$，内层 $k$ 循环访问：

$$
B[0][j]\rightarrow B[1][j]\rightarrow\cdots\rightarrow B[n-1][j]
$$

因为 B 是 Row-major，连续访问的是不同行。

假设 $n\ge\mathcal B$，那么每行的这些元素通常位于不同的 Cache Line 中。

因此，遍历 B 的一列需要访问：

$$
\boxed{n\text{ 条不同的 Cache Line}}
$$

### 2\. 如果 Cache 装不下这些 Line 呢？

举个例子：

$$
n=8,\quad M=8,\quad\mathcal B=2
$$

Cache 最多能保存：

$$
M/\mathcal B=4\text{ 条 Line}
$$

但遍历 B 的一列，需要访问 8 条不同的 Line。

当访问：

$$
B[0][0],B[1][0],\ldots,B[7][0]
$$

前面加载的 Cache Line 会因为 LRU 不断被淘汰。

接下来访问第二列：

$$
B[0][1],B[1][1],\ldots,B[7][1]
$$

虽然 `B[0][1]` 与 `B[0][0]` 属于同一条 Cache Line，但之前那条 Line 已经被淘汰，所以又产生 Miss。

**这就是关键：B 相邻两列之间本来有空间局部性，但 Cache 太小，无法保留这些数据。**

### 3\. 得到 Case 1 的结论

课件 Case 1 考虑的是矩阵维度相对于 Cache 能存储的 Line 数足够大：

$$
n>c\frac M{\mathcal B}
$$

其中 $c$ 是分析中使用的常数。

在这种大矩阵、LRU 的情形下，B 的列访问会导致 $\Theta(n^3)$ 量级的 Miss。

而矩阵乘法的 B 元素访问总次数是：

$$
\underbrace{n}_{i}
\times\underbrace{n}_{j}
\times\underbrace{n}_{k}
=n^3
$$

因此：

$$
\boxed{
\begin{aligned}
W(n)&=\Theta(n^3)\\
Q(n)&=\Theta(n^3)
\end{aligned}
}
$$

这正是课件 P78 的 Case 1 结论。fileciteturn0file0L1256-L1275

# 二、Memory Hierarchy

## 1\. Latency、Throughput、Bandwidth

| 概念 | 定义 | 记忆方式 |
|--------|--------|--------|
| Latency | 完成一次操作的延迟 | 一次要多久 |
| Throughput | 单位时间实际处理量 | 实际每秒多少 |
| Bandwidth | 理论最大传输速率 | 最多每秒多少 |

# 三、Blocking / Tiling

我们之前已经完整推导过，这里整理成公式。

定义：

$$
\begin{aligned}
n&:\text{矩阵维度}\\
S&:\text{Tile 边长}\\
M&:\text{Cache 容量}\\
\mathcal B&:\text{每条 Cache Line 的元素数}
\end{aligned}
$$

此处统一用元素数量计量 $M,\mathcal B$。

## 1\. 一个 Tile

$$
\boxed{
\begin{aligned}
W_{\text{tile}}&=\Theta(S^3)\\
D_{\text{tile}}&=\Theta(S^2)\\
Q_{\text{tile}}&=O(S^2/\mathcal B)
\end{aligned}
}
$$

## 2\. 整个矩阵

$$
\boxed{
\begin{aligned}
N_{\text{tile}}&=(n/S)^3\\
W(n)&=\Theta(n^3)\\
Q_{A+B}&=O(n^3/(\mathcal BS))\\
Q_C&=O(n^2/\mathcal B)
\end{aligned}
}
$$

因此：

$$
\boxed{
Q_{\text{blocked}}
=O\left(\frac{n^3}{\mathcal BS}+\frac{n^2}{\mathcal B}\right)
}
$$

## 3\. Tile Size

三个 Tile 同时放进 Cache：

$$
3S^2\le M
$$

于是：

$$
S=O(\sqrt M)
$$

理想情况下选用：

$$
S=\Theta(\sqrt M)
$$

得到：

$$
\boxed{
Q_{\text{blocked}}
=O\left(\frac{n^3}{\mathcal B\sqrt M}+\frac{n^2}{\mathcal B}\right)
}
$$

这些是我们基于课件 Blocking 思路进一步推导的结果，需要理想化的容量、对齐和数据复用假设；课件 P37–44 本身主要讲分块方法。fileciteturn0file0L527-L651

**记忆重点：Blocking 不改变 $\Theta(n^3)$ 的运算量，而是减少 Cache Miss。**

# 四、Double Buffering

这一块公式很适合出计算题。

定义：

$$
\begin{aligned}
N&:\text{数据批次数}\\
T_L&:\text{每批加载时间}\\
T_C&:\text{每批计算时间}
\end{aligned}
$$

## 1\. Single Buffer

加载和计算顺序执行：

$$
\boxed{T_{\text{single}}=N(T_L+T_C)}
$$

## 2\. Double Buffer

当前批计算与下一批加载重叠：

$$
\boxed{
T_{\text{double}}\approx T_L+(N-1)\max(T_L,T_C)+T_C
}
$$

## 3\. Speedup

$$
\boxed{
S(N)=\frac{N(T_L+T_C)}
{T_L+(N-1)\max(T_L,T_C)+T_C}
}
$$

当 $N\to\infty$：

$$
\boxed{
S_\infty=\frac{T_L+T_C}{\max(T_L,T_C)}\le2
}
$$

最大 2 倍的条件：

$$
\boxed{T_L=T_C}
$$

注意，2 倍是忽略同步等开销且批次数趋于无穷时的理论极限。fileciteturn0file0L929-L956

# 五、Cache Mapping

这是 L02 非常重要的计算部分。

## 1\. 三种 Cache 结构

| 类型 | 一个 Memory Block 能放哪里？ | Associativity |
|--------|--------|--------|
| Direct Mapped | 唯一 Slot | 1-Way |
| k-Way Set Associative | 固定 Set 内任意 Way | k-Way |
| Fully Associative | 任意 Slot | 所有 Lines |

统一定义：

$$
\boxed{
\text{Number of Sets}=\frac{M}{k\mathcal B}
}
$$

其中这里 $M,\mathcal B$ 都以 Bytes 计。

## 2\. 地址拆分

$$
\boxed{\text{Address}=[\text{Tag}\mid\text{Index}\mid\text{Offset}]}
$$

对于 $w$\-bit 地址：

| 字段 | bits |
|--------|--------|
| Offset | $\log_2\mathcal B$ |
| Set Index | $\log_2(M/(k\mathcal B))$ |
| Tag | $w-\log_2(M/k)$ |

对于 Direct Mapped，代入 $k=1$：

$$
\boxed{
\begin{aligned}
\text{Tag}&=w-\log_2M\\
\text{Index}&=\log_2(M/\mathcal B)\\
\text{Offset}&=\log_2\mathcal B
\end{aligned}
}
$$

## 3\. 地址映射公式

$$
\boxed{
\begin{aligned}
\text{Block ID}&=\left\lfloor\frac a{\mathcal B}\right\rfloor\\
\text{Set Index}&=\text{Block ID}\bmod\frac{M}{k\mathcal B}\\
\text{Tag}&=\left\lfloor\frac a{M/k}\right\rfloor\\
\text{Offset}&=a\bmod\mathcal B
\end{aligned}
}
$$

条件：字节编址，相关容量及 Set 数是 2 的整数次幂。

判断 Cache Hit：

$$
\boxed{\text{Hit}\iff\exists\text{ Valid Way with matching Tag}}
$$

Index 确定 Set，Tag 判断是否为所需 Block，Offset 定位 Block 内的字节。fileciteturn0file0L1026-L1109

# 六、Cache Miss Types

| 类型 | 原因 |
|--------|--------|
| Cold Miss | 首次访问某个 Block |
| Capacity Miss | 相同容量的 Fully Associative 参考 Cache 也无法保留 |
| Conflict Miss | 当前 Set 映射导致 Miss，但参考 Fully Associative 可以 Hit |
| True Sharing Miss | 多核共享同一数据导致一致性失效 |
| False Sharing Miss | 不同数据在同一 Cache Line，导致一致性失效 |

课件列出了这些类型；我们之前使用 LRU 作为 Capacity / Conflict 分类的 Fully Associative 参考策略。fileciteturn0file0L1111-L1124

LRU 的规则：

$$
\boxed{\text{Evict Least Recently Used Block}}
$$

注意：Cache Hit 也会更新 LRU 的使用顺序。
